# Proposal

## Why

지금은 한 번 저장한 기록을 고칠 방법이 없어서, 오타 하나를 고치려 해도 같은 내용을 새로 써야 하고 목록에 비슷한 기록이 겹쳐 쌓인다. 작성과 목록이 자리 잡았으니, 다음으로 이미 쓴 한 줄을 바로잡는 수정 기능을 더한다.

## What Changes

- 목록의 각 기록에 [수정] 버튼을 둔다. 누르면 그 줄이 기존 내용이 채워진 입력창과 [저장]·[취소] 버튼으로 바뀐다.
- Enter 키나 [저장]으로 수정을 확정하고, Esc 키나 [취소]로 수정 전 내용으로 되돌린다.
- 수정해도 원래 작성 날짜·시간과 목록 속 위치는 바뀌지 않는다. 대신 수정 시각을 함께 저장하고, 수정된 기록에는 "(수정됨)"을 표시한다.
- 수정 입력도 새 기록과 같은 규칙을 따른다. 앞뒤 공백을 제거하고 최대 100자이며, 내용을 모두 지우거나 공백만 남기고 저장하면 저장을 막고 "내용을 입력해 주세요." 경고를 보여 준다.
- 내용이 바뀌지 않은 채 저장하면 수정으로 치지 않는다.
- 한 번에 한 기록만 수정할 수 있다.
- 수정 내용도 `localStorage`에 저장되어 새로고침 후에도 유지되고, 저장에 실패하면 안내를 보여 주며 수정 중인 내용을 잃지 않는다.

범위 밖(이번 변경에서 하지 않음):

- 기록 삭제 (빈 내용으로 수정해도 삭제되지 않는다)
- 작성 날짜·시간 자체를 바꾸는 기능
- 수정 이력(이전 내용) 보관

## Capabilities

### New Capabilities
(없음)

### Modified Capabilities
- `diary-entries`: 저장된 기록의 내용을 수정하는 요구사항과, 수정된 기록을 목록에 표시하는 요구사항을 더한다. 기존 요구사항(작성, 목록 순서 등)의 동작은 바뀌지 않는다.

## Impact

- 코드: `app.js`(수정 로직과 목록 렌더링), `index.html`은 바뀌지 않거나 최소한만 바뀐다.
- 데이터: 기록 객체에 선택 필드 `updatedAt`(수정 시각)이 더해진다. 기존 기록은 이 필드가 없어도 그대로 읽히므로 저장 키(`diary.entries.v1`)와 형식은 호환된다.
- 외부 의존성 변화 없음.
